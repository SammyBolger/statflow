# StatFlow — Repository Audit & Recovery Plan

## Context

`~/Desktop/statflow` is a working MLB-only prediction pipeline (bronze/silver/gold parquet → DuckDB → XGBoost → MLflow → Prefect → Streamlit + FastAPI, hosted state on Cloudflare R2, deployed to Streamlit Community Cloud). The **intended** scope per the user is a multi-league (MLB, NBA, WNBA, NFL, NHL) automated sports-intelligence platform. Two live production bugs currently break the daily and weekly workflows; the local codebase itself is clean (182 tests passing, ruff green) but scope-wise only ~1/5 of the intended platform exists.

This report inventories what exists, what's broken, what's fragile, and stages a recovery plan across four horizons: immediate fixes, foundation refactor, MVP feature work, and later enhancements. **No code has been modified during this review.**

## 3. Current end-to-end data flow

```
MLB Stats API (schedule, boxscore, plays, transactions)
    │  requests + retry (429/5xx)
    ▼
data/bronze/{schedule,boxscores,plays,transactions,odds}/date=YYYY-MM-DD/*.parquet
    │  ingested_at timestamp per row; JSON payload preserved verbatim
    ▼  DuckDB SQL over parquet globs
data/silver/{games,team_game_stats,pitcher_game_stats,transactions,odds}/*.parquet
    │  QUALIFY ROW_NUMBER() dedup by PK, latest ingested_at wins
    ▼  DuckDB SQL over parquet, six intermediates → final assembly
data/gold/{team_rolling,pitcher_form,bullpen_form,park_factors,roster_activity,features}/*.parquet
    │  load_features → split_by_season → make_classification_xy / make_regression_xy
    ▼
XGBoost + LR/Ridge → MLflow (sqlite:///mlartifacts/mlflow.db)
    │  promotion gate tags `promoted=true` on best val log_loss / MAE
    ▼
data/gold/predictions/date=YYYY-MM-DD/predictions.parquet
    │  join to silver.games where status='Final'
    ▼
data/gold/prediction_outcomes/prediction_outcomes.parquet   (grading table)
    │
    ├──► Streamlit dashboard (reads gold + silver parquet)
    ├──► FastAPI service     (reads gold parquet)
    └──► GH Actions push → Cloudflare R2 (silver + gold + mlartifacts)
```

**Schedule.** GH Actions `daily.yml` runs `python -m statflow.flows` at 11:00 UTC. `retrain.yml` runs `python -m statflow.models train` at 12:00 UTC Sundays and commits new model cards back to main.

## 4. What currently works

- 182 pytest tests pass locally; ruff lint + format both clean; pre-commit hooks green.
- 6 seasons of MLB history backfilled locally (2019–2024 train, 2025 val, 2026 test). Local retrain shows the model narrowly beats baseline on winner val log_loss (0.6874 vs 0.6896).

## 5. What is incomplete or broken

### 5a. Live production failures

**Bug 1 — Daily pipeline broken on GH Actions since 2026-07-31 (4 consecutive failures).**
- **Error:** `requests.exceptions.HTTPError: 401 Client Error: Unauthorized for url: https://api.the-odds-api.com/v4/sports/baseball_mlb/odds?apiKey=&regions=us&markets=h2h%2Ctotals&oddsFormat=american`
- **Root cause:** `.github/workflows/daily.yml` sets `ODDS_API_KEY: ${{ secrets.ODDS_API_KEY }}`. When the secret is absent, GitHub sets the env var to the **empty string**, not unset. `src/statflow/ingest/odds.py` guards with `if api_key is None:` — but `""` is not `None`, so the code proceeds to call the API with an empty key → 401 → uncaught exception → the whole flow dies at ingest step.
- **Blast radius:** four missed days of ingest, predictions, and prediction_outcomes updates.

**Bug 2 — Weekly retrain broken on GH Actions since at least 2026-07-26 (based on failure history).**
- **Error:** `ValueError: Input contains NaN.` at `sklearn.metrics.log_loss`, preceded by `n_train=0 n_val=0 n_test=31`.
- **Root cause:** `retrain.yml` runs `python -m statflow.models train` with no `--seasons` arguments. CLI defaults are `--seasons=[2024] --val-seasons=[2025] --test-seasons=[2026]`. R2's `features.parquet` still contains only 2026 data (my local 2019–2024 backfill was never pushed to R2 — the manual push step was flagged at end of the last working session and never executed). So training data is empty, `HomeAlwaysWinsBaseline.p` becomes NaN, and log_loss can't be computed.
- **Blast radius:** no fresh model since 2026-07-30; predict.py continues to serve the promoted 2026-07-30 run.

**Bug 3 — Odds ingest was never validated end-to-end.**
- `data/bronze/odds/` does not exist locally. The unit tests mock the API but no real call has been made. The 401 path is exactly the untested code path.

### 5b. Silent quality issues

- The `refresh_outcomes` step of the daily flow will still succeed with 0 new rows for the next several days until the two production bugs are fixed and the daily flow actually populates predictions for games that then complete.
- MLflow's Default experiment (`id=0`) exists and is empty — cosmetic, not harmful.
- `notebooks/` and `scripts/` directories are empty. Either remove them or add real content.
- `.devcontainer/devcontainer.json` runs `updateContentCommand` looking for `packages.txt` and `requirements.txt`, neither of which exist. The container `postAttachCommand` starts Streamlit but the project uses `uv`, not `pip`. Whole devcontainer config is misleading dead code.
- Two model-card markdown files from the local retrain are untracked. Either commit or add a `docs/model_cards/*/` pattern to `.gitignore`.

### 5c. Scope gaps vs the intended platform

- **Sports:** intended = MLB + NBA + WNBA + NFL + NHL. Actual = MLB only. `src/statflow/sports/{mlb,nba}/` are placeholder directories with a README and empty `__init__.py`; no ingest/silver/features code has been moved into them. WNBA/NFL/NHL directories do not exist at all.
- **`src/statflow/core/`** exists as an empty directory. The multi-sport ADR (`docs/adrs/0001-multi-sport-layout.md`) describes a `core/` package holding sport-agnostic training / metrics / MLflow / R2 / dashboard components; nothing has been moved in.
- **Odds ingest** is MLB-only (hard-codes `baseball_mlb` sport key). No generalization for the four other leagues.
- **Dashboard** shows one sport only; no per-sport tabs or league picker.
- **API** exposes one prediction stream; no `/leagues/{league}/predictions` shape.
- **MLflow experiments** are `statflow_winner` and `statflow_runs`; no league dimension baked into experiment names.

### 6b. Data-integrity / leakage / correctness risks

| Risk | Reality in code |
|---|---|
| **Rolling-window leakage** | Structurally prevented with `ROWS BETWEEN N PRECEDING AND 1 PRECEDING`; `tests/features/test_team_rolling.py::test_window_excludes_current_game_no_leakage` is a canary. Solid. |
| **Scaffold-row leakage** | Fixed in the 2026-07-30 commits (`team_rolling.sql`, `bullpen_form.sql` now `CASE WHEN status='Final'` guard). Still worth writing a regression test that seeds a scheduled zero-stat row and asserts it does not depress the rolling mean. |
| **Team-identifier consistency** | Silver.games uses MLB team IDs (integers) end-to-end. But the model was trained on rows where `status='Final'` — no distribution-shift check exists between training-time features and inference-time features. Low risk today, worth monitoring. |
| **Feature-column drift** | `dashboard/app.py:154` explicitly checks that R2's cached `features.parquet` still has every column the loaded model expects, and hides the explanations panel if not — good defensive code Sammy already added. `predict.py` will still crash if the columns diverge; the drift is caught by a try/except in `_explanations_for` but not around `winner_model.predict_proba`. |

## 8. Storage design

- **Bronze:** local filesystem Hive-partitioned parquet (`data/bronze/{table}/date=YYYY-MM-DD/*.parquet`). Contains raw JSON in a `payload` column, plus `ingested_at`. Grows unbounded but is regenerable — hence excluded from R2, cached instead in GH Actions cache keyed by `github.run_id`.
- **Silver:** local parquet, one file per table (no partitioning). Rebuilt from scratch on every daily run. Small (13 MB).
- **Gold:** local parquet, one file per table + one predictions partition per date. Rebuilt on every daily run.
- **MLflow tracking:** SQLite (`sqlite:///mlartifacts/mlflow.db`) + local `mlartifacts/` for logged model artifacts. Absolute paths inside MLflow get rewritten by `storage/r2.py` after every pull so the DB is portable between laptop and GH runner.
- **Cloudflare R2:** source of truth for `data/silver`, `data/gold`, `mlartifacts` across all environments (laptop, GH Actions, Streamlit Community Cloud). No versioning/backup layer.
- **No relational database.** No dbt-materialized state outside DuckDB in-memory + parquet.
- **No secrets store.** All secrets in GH Actions secrets + local `.env` (gitignored, never committed).

## 9. Current ML setup

- **Feature set (`models/data.py::FEATURE_COLS`):** 23 features covering team rolling offense/defense (L10), team win% (L10), team days-rest, starting-pitcher form (L5 ERA, K/9, days rest), team bullpen form (L10 ERA + L3 IP fatigue), rolling IL activity, park factor, day-game flag, month.
- **Targets:** `target_home_win` (binary), `target_total_runs` (integer regression).
- **Splits:** by season. Time-based only. Training on 2019–2024, val on 2025, test on 2026 (per local retrain), OR the CLI default `--seasons 2024 --val-seasons 2025 --test-seasons 2026` (which is what production retrain has been using — and is now broken).
- **Models:** `HomeAlwaysWinsBaseline` (constant), `LogisticRegression` (imputed + scaled), `XGBClassifier` (150 trees, depth 3, min_child_weight 8). For runs: `MeanRunsBaseline`, `Ridge`, `XGBRegressor` (300 trees, depth 4, min_child_weight 5). CalibratedClassifierCV was removed on 2026-07-30 because it collapsed predictions to near-constant values.
- **Metrics:** classification — accuracy, log_loss, brier; regression — MAE, RMSE, within-1, within-2. All logged per split to MLflow.
- **Promotion gate:** `_apply_promotion_gate` in `train.py` tags the current run `promoted=true` iff it beats the previously-promoted run's val metric (log_loss lower is better for winner, MAE for runs). `predict.py` reads the latest run tagged `promoted=true`.
- **Model cards:** auto-generated to `docs/model_cards/<experiment>/<run_id>.md` per retrain. Committed back to main by `retrain.yml`.
- **Latest baseline comparison (local, 6-season retrain, 2026-07-30):**

| Split | Metric | Baseline | XGBoost |
|---|---|---|---|
| val | log_loss | 0.6896 | **0.6874** |
| test | log_loss | 0.6924 | **0.6917** |
| val | runs MAE | 3.64 | 3.63 (Ridge: 3.61) |
| test | runs MAE | 3.62 | 3.63 (Ridge: 3.60) |

Model narrowly beats the baseline; realistic for a public-data MLB model.

## 15. Questions to answer before implementation begins

1. **Scope commitment:** is the MVP truly all 5 leagues, or is MLB + one more (NBA?) the resume-worthy target? The former is 3–6 days of feature work minimum; the latter is 1–2 days.
2. **Odds provider:** does Sammy have or plan to acquire a paid data source (SportsDataIO, TheOddsAPI paid tier, Sportradar), or stay on free tiers? Free tier limits mean odds ingestion can run ~once per league per day; nothing intraday.
3. **NFL cadence:** NFL is weekly (Thu/Sun/Mon), not daily. Do we run a separate weekly workflow for NFL, or gate the daily flow on "any league in season today"?
4. **Historical backfill scope:** how far back for each league? MLB has 2019–present locally; NBA usually wants 2015+ for pace/four-factors era; NFL only really needs 2018+ (post-EPA-model changes). Costs disk + retrain compute.
5. **Model per league or model per (league, target)?** Currently MLB uses one classifier + one regressor. Same shape for other leagues, or league-specific targets (NBA point differential vs. spread; NFL EPA vs. yards vs. total points)?
6. **R2 vs. local storage:** does the multi-league dataset stay in R2, or is it time to introduce a relational database?
7. **Deployment target:** dashboard stays on Streamlit Community Cloud, or move to Fly.io / Railway / Vercel? Multi-league dashboards may hit Streamlit Cloud's memory/CPU limits.
8. **Interview timing:** when does Sammy want this on his resume? That gates whether we ship 5 leagues or 2.
9. **Attribution/legality:** `stats.nba.com` and `stats.wnba.com` are unofficial; scraping them is a legal gray area even for personal use. Fine for a portfolio project but worth flagging.
